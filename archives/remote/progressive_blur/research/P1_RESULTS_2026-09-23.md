# P1 paired pilot results — YOLOv8n with progressive background blur

Date: 2026-09-23  
Status: verified complete

## Scope

P1 is a short mechanism-screening experiment, not a publication result. It
compares a scratch-trained YOLOv8n baseline (A0) with the full learned
progressive-blur front end (D/PGB). The final VOC2007 test set was not used.

## Controlled setup

- Dataset: PASCAL VOC2007+2012 trainval, deterministically split with seed 2027.
- Train: 14,896 images; development validation: 1,655 images.
- Model initialization: `yolov8n.yaml`, no pretrained weights.
- Training: 20 epochs, global batch 64, image size 640, seed 2027.
- Runtime: BF16, four physical RTX 3090 GPUs numbered 4–7; NUMA node 1.
- Workers: 4 per rank.
- Augmentation: mosaic, MixUp, CutMix, copy-paste, geometric, flips and HSV
  disabled in both groups to isolate the mechanism.
- Model selection: maximum development mAP50–95.
- PGB: 38,513-parameter blur-map front end; map-loss weight 1.0; inference mix
  0.5; mix 0 for epochs 1–5 and linearly ramped during epochs 6–10.

## Best-checkpoint comparison

Both methods reached their best development mAP50–95 at epoch 12.

| Metric | A0 YOLOv8n | D/PGB | PGB - A0 |
|---|---:|---:|---:|
| Precision | 0.42630 | 0.39286 | -0.03344 |
| Recall | 0.29020 | 0.31732 | +0.02712 |
| mAP50 | 0.29178 | 0.29113 | -0.00065 |
| mAP50–95 | 0.16173 | 0.15921 | -0.00252 |

PGB trades precision for recall but does not improve either primary AP metric
under this pilot. The AP differences are small: -0.065 percentage points for
mAP50 and -0.252 percentage points for mAP50–95. This is a negative/inconclusive
P1 result, not evidence that the proposed method improves detection.

## Final-epoch comparison

| Metric | A0 epoch 20 | D/PGB epoch 20 | PGB - A0 |
|---|---:|---:|---:|
| Precision | 0.37799 | 0.40453 | +0.02654 |
| Recall | 0.29110 | 0.25930 | -0.03180 |
| mAP50 | 0.26371 | 0.25606 | -0.00765 |
| mAP50–95 | 0.14023 | 0.13711 | -0.00312 |

The fall after epoch 12 in both groups indicates that 20-epoch scratch training
under weak augmentation overfits the development split. Final-epoch metrics are
therefore secondary; the predeclared best-checkpoint comparison is primary.

## Cost and stability

- Recorded end-to-end training/validation time: A0 312.328 s; PGB 738.908 s.
- PGB/A0 time ratio: 2.366x (136.6% extra elapsed time in this run).
- This is training-pipeline time, not a measured inference-latency ratio.
- PGB train map loss ended at 0.10548 and development map loss at 0.10795;
  neither diverged.
- Both runs contain exactly 20 finite result rows. `best.pt` and `last.pt` for
  both runs are readable and finite, and PGB checkpoints contain the front end.
- No MCE, SIGBUS or kernel memory-failure event was observed during the final
  monitoring window. GPUs 0–3 were not used.

## Interpretation and decision

The current geometric blur-map supervision is learnable and the complete
training/inference/checkpoint pipeline works, but the full PGB transformation
does not outperform the baseline in this controlled pilot. Its recall increase
is offset by lower precision, while its computational overhead is substantial.

The next experiment should not simply lengthen this exact configuration. A
causal control is needed first:

1. Run an identity-front-end/wrapper control to quantify whether the wrapper,
   schedule or optimization path changes results even without blurring.
2. Evaluate simple oracle and fixed-blur controls to determine whether
   background blur itself has a useful upper bound on VOC.
3. Inspect saved reference maps, predicted maps and processed images; quantify
   target-region leakage and foreground/background map errors.
4. If blur remains promising, reduce filtering cost and test weaker mix values
   before committing to multiple seeds or long training.
5. Do not touch the VOC2007 final test set until a method is selected on the
   development split.

## Audit correction

The post-run comparison initially displayed the best epoch as 13 because it
added one to Ultralytics' already one-based `results.csv` epoch. Only the label
was wrong; metrics and checkpoints were unchanged. The reporting code was
corrected and the independent checkpoint audit rerun successfully. During that
rerun, a missing project-root path caused Ultralytics to install an unrelated
PyPI package named `pgb`; it was immediately uninstalled. The audit script now
prepends the research root before checkpoint loading and resolves
`/home/ubuntu/rz/progressive_blur_detection_research/pgb/__init__.py`.

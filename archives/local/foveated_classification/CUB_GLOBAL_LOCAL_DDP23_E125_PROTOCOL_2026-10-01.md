# CUB全局—局部双视图配对实验：GPU2、3 / 实际125轮

2026-10-01。用户授权同时使用物理GPU2、3。这里的“双卡”指一个模型用DDP分布式训练，不是两组分别占一张卡。两组依次运行，避免竞争同一对卡；原有其他人的作业不停止、不修改。本文记录新实验，不能改写已经验收的A–F结果。

## 研究问题与组别

主实验G4为“原图全局视图＋同图目标局部视图”；对照G5为“固定无信息全局视图＋完全相同的局部视图”。两组模型、初始化、采样、增强、训练预算和评估口径相同，唯一实验变量是全局视图携带的信息。

G4若优于G5，说明这套双视图实现能够利用全局视图中的额外信息，但不能直接证明收益全部来自背景：全局图还包含目标的原生尺度呈现、布局和背景。G5保留完整的两路计算，以控制结构和计算路径，不是省计算的单路裁剪模型。零输入也可能改变批归一化统计，因此因果解释需要保守。

本轮只落实G4/G5，不增加新的裁剪、分割、模糊或其他网络组。

## 图像处理

原始RGB不缩放，居中补边到500×500。局部图按官方GT框裁剪，无外扩；左/上取floor，右/下取ceil并裁到有效图内，右/下端点不包含。局部长边等比例放大至500，短边四舍五入，Pillow RGB BICUBIC插值，再居中补边到500×500。补边色固定为训练集RGB均值的整数近似(124,128,111)，随后使用既有官方训练集统计进行标准化。放大不会恢复原图不存在的细节。

训练时先对整张有效原图执行既有确定性水平翻转与亮度、对比度、饱和度增强，再生成两路图。翻转时同时反射已裁边的半开整数框，避免小数取整漂移。两个组的局部输入对相同seed/epoch/ID逐位一致。测试不做随机增强。

G5全局输入是标准化后固定的全零3×500×500张量；每张图都相同，不保留原图尺寸补边形状，不使用逐图均值、不画标注、不提供位置信息。局部输入仍读取GT框。训练和官方test均用真实框，因此两组都是Oracle，不能描述成不依赖标注的可部署分类系统。

六张已批准预览来自官方训练集。正式未增强输入必须与`previews/cub_global_local_gt_long500_v1_2026-10-01`的干净全局/局部PNG逐像素一致；带绿框或文字的展示图绝不进入模型。

## 模型与优化

同一个scratch ResNet50编码两路视图，删除原分类层。两路2048维全局池化特征拼接为4096维，线性层输出200类，使用一次融合交叉熵，无额外单分支分类损失。两路共用权重，不是两个独立ResNet50；参数量以GPU短测报告为准。

| 设置 | 冻结值 |
| --- | --- |
| 数据 | CUB官方train5994 / test5794，200类 |
| 初始化与种子 | 从零、seed2005，两组相同 |
| 实际训练 | 各125轮，原生循环在125轮结束，无外部SIGTERM停止器 |
| 学习率计划 | 保留200轮余弦计划前125项；并非以125为余弦终点 |
| SGD | LR0.025、最低1e-5、warmup5、momentum0.9、weight decay0.0005 |
| 全局有效batch | 64对图；一对对应一个样本和一个类别标签 |
| 每卡microbatch | 8对，即16幅视图；两卡合计16对，累积4次 |
| DataLoader | workers4总计，每卡2；非持久worker |
| 测试batch | 每卡16对，两卡32对 |
| 分布式归一化 | SyncBatchNorm，单进程单GPU；每次训练前向汇总32幅视图统计 |
| 精度 | FP16 AMP；共同初始梯度缩放1024，记录实际跳步数 |
| 硬件 | 物理GPU2、3共卡，CPU/内存绑定NUMA0 |
| 软件 | 既有`/home/ubuntu/rz/yolo_study/.conda/yolo26`，不修改共享依赖 |

两卡不重复、不丢弃、不填充训练或测试样本。按每轮全局排列将每个64对更新组分成16对microbatch，再分给两卡。最后42对分成16、16、10，各卡8、8、5，尾组按实际42归一化。每轮94个更新组；AMP若跳过更新，则分别记录真实optimizer_steps和amp_skipped_steps，不把跳步算成成功更新。

DDP平均两卡梯度，因此每卡反传标量为`本卡逐样本交叉熵之和 × 2 / 当前全局更新组样本数`；非末个microbatch在no_sync内执行前向和反向。CPU解析梯度核验必须与整批均值一致。原理参见[PyTorch DDP](https://docs.pytorch.org/docs/stable/generated/torch.nn.parallel.DistributedDataParallel.html)和[SyncBatchNorm](https://docs.pytorch.org/docs/main/generated/torch.nn.SyncBatchNorm.html)。

## 验收与安全边界

CPU检查包括11788个框裁边非空、6张预览逐像素一致、两组局部增强一致、空白图严格全零、全量采样无重复遗漏、94个更新组与42对尾组、64/42批梯度缩放解析核验。

GPU短测使用固定随机抽取的170张训练图和34张test图，检查3个更新组、两卡权重一致、损失有限、尾批处理和实际显存。短测仅验程序，不解释其中的准确率。2026-10-01首次默认AMP初值65536短测发生1次跳步，正式启动被拦截；该诊断JSON/日志保留，随后两组共同改为1024并重新核验。新设置属于本次配对共同设置，不能声称与旧A–F逐位复现。

每次新GPU作业前检查GPU2/3 UUID和剩余显存、NUMA0保守可回收内存预算、全机可用内存/压力、当前boot EDAC及内核MCE/SIGBUS。只允许这两张卡，低显存或新增硬件错误时不启动下一组。现有上一boot Socket1 BERT错误重放是历史风险，当前计数清零不代表硬件修复；不迁移其他作业内存、不清空共享缓存。

任务专属顺序管理器在G4正常退出、无本任务残留进程且CPU严格审计通过后，才重新检查资源并短测/启动G5。失败或断电不从损坏检查点强制恢复，不重复启动，不机械终止仍正常的训练。保存模型、优化器、AMP、两rank RNG、配置/统计/框/源码哈希、完整CSV及状态；普通训练状态文件不能替代真实进程核查。

末轮主指标为固定第125轮train/test Top1、Top5、交叉熵；best仅作次要观察。严格验收要求125个连续有限epoch、5994/5794真实样本数、每轮94个更新组、学习率与冻结200轮计划一致、best/last可加载且哈希一致。汇总训练及完整test耗时，不将共卡耗时视为独占算力的公平速度比较。

官方test逐轮查看过，非盲测；仅seed2005。旧A–F和本次DDP/SyncBN、运行环境、两路计算不完全相同，历史组只作上下文，主归因比较是G4对G5。不根据test成绩调整本轮参数。

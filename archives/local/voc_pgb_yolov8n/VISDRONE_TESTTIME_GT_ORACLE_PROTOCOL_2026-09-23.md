# VisDrone 推理期真实框保护式模糊：预先固定的测试协议

记录时间：2026-09-23 20:23 CST。该测试是用户要求的 **GT Oracle 诊断**，与此前的“预测框保护”实验分开存储、报告，绝不将真值框参与处理后的 AP 作为正常/可部署检测性能。

## 固定问题

冻结已有 YOLOv8n scratch、960、seed2027、125轮的 `best.pt`，不重新训练。在 VisDrone 官方来源 val 548 图上，先使用**当前 LetterBox 输入坐标系**中的真实检测框保护原像素，框外做高斯背景模糊，再用同一权重验证。真实框来自评估数据标签，正式未知图像没有这些信息。因框的形状和位置会被编码在处理后图像中，结果还存在标签泄露，不可当普通模型提点。

## 对照和处理

- raw：原图，完全不处理。
- sham：构建真实框保护列表并做图像张量往返，但输出原像素；AP 应当与 raw 相同。
- light / medium / heavy：在 LetterBox 后 `imgsz=960` 输入上，分别做 `sigma=3/8/16` 高斯模糊。真实框内像素保持完全不变；不额外扩大框（margin fraction=0、minimum margin=0），框外保护权重用 `sigma=8` 平滑过渡。多目标的所有框均保护，重叠处取并集。

与此前预测框实验相比，本次不仅换了框来源，也取消了10%/8px的额外外扩，因此不能把二者差异全部归因为定位来源。如果 GT Oracle 仍下降，可判定这一精确框保护设置也不能拯救“原图训练、推理才背景模糊”的方案；如果提升，需另做严格同保护圈、无真值泄露的实验验证。

## 统一评估与停止判据

使用同一检查点、数据 YAML、val548、`imgsz=960`、`batch=16`、`workers=4`、`conf=.001`、NMS IoU `.7`、`max_det=1000`、FP32、rect=True，不触碰 test-dev。主指标 mAP50–95，辅以 mAP50、逐类 AP、保护区域比例、平均像素改变量及整个原型流程耗时。仅在 sham 的 AP 与 raw 完全一致、GT 坐标单测及小样本检查通过后进行全量三档。结果无论升降都记录，不在本轮对 sigma、边缘或保护圈调参。

只用物理 GPU4（若空闲），进程级 `CUDA_VISIBLE_DEVICES=4`；用 `numactl --cpunodebind=0 --membind=0`，不动全局环境与其他进程。由于此前 NUMA1 出现不可纠正内存错误，运行前后检查 EDAC/MCE。NUMA0 当前计数为0只代表本 boot 暂未观测到错误，不保证硬件健康。发生本任务错误则保留部分结果并如实报告，不强行掩盖。

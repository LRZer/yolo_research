# VisDrone 冻结检测器小框专属局部融合：试验前固定协议

记录：2026-09-24 12:56 CST。此协议在新一轮 test-dev 推理前落盘；**不是新方法、不是正式盲测或官方 VisDrone 指标**。此前 val548 已反复用于研究，历史项目也查看过 test-dev；本次只是固定规则后的独立图像集复核，不据此反复改阈值。

## 问题和单一改动

已封存 val548 结果：整图960 AP50–95=0.230872，整图+热度top4局部裁剪=0.226803。固定 conf≥0.25 的来源审计中，bus/truck 的局部分支虽新增真阳性，也带来更多假阳性。检验假设：**局部放大分支只用于补充整图下仍属小尺度的目标，是否能减少大类误报，同时保留小目标收益？**

复用完全相同的 scratch YOLOv8n/960/seed2027/125轮 `last.pt`、全图热度top4选格、4×4网格、每格10% halo、每裁剪960推理、统一 `multi_label=True` / conf0.001 / NMS IoU0.7 / max_det1000 / 同一 YOLO 转换标签评价器。三组仅为：A整图；B整图+四格原始融合；C整图+相同四格，但进入跨分支NMS前过滤局部分支预测。**整图候选永远不过滤**。

唯一新增规则：将局部分支的回映框宽高换算为单次全图960 letterbox 比例 `960/max(原图宽,原图高)` 下的像素长度；仅当 `max(换算宽,换算高) <= 64` 时允许该框进入原合并器。阈值64取自 [AutoFocus ICCV 2019](https://openaccess.thecvf.com/content_ICCV_2019/papers/Najibi_AutoFocus_Efficient_Multi-Scale_Inference_ICCV_2019_paper.pdf) 的小尺度上界思路；这里改用最长边以保守排除细长大框，**并非忠实复现 AutoFocus**。不使用真实框作裁剪选择或预测过滤。

先运行纯函数自测和 test-dev 前16张图冒烟：A/B应与封存旧代码同口径，C只有局部分支过滤。然后一次性在官方来源 test-dev 1,610张图及其既有转换标签上运行三组；不更改权重、数据、已有结果或共享环境。主要指标为内部 mAP50–95，附 mAP50、逐类AP、P/R解释、候选保留数与计算预算。比较 B→C 是本规则效果；比较 A→C 是实际是否胜过单次整图。若 C 仍不及 A，则此路线仍 no-go，即使优于 B。不能以不变的五次960调用声称加速，也不能把任何结果称论文创新。

硬件：仅物理GPU0、NUMA0，进程级绑定；跑前跑后检查GPU占用、EDAC mc0/mc1 及近窗 MCE/SIGBUS。历史 MC1 不可纠正错误尚未修复，新boot计数为0不代表硬件健康。GPU7他人进程不可触碰。

不在 test-dev 上依据结果再调阈值。若出现效果，后续才研究 train 内设计划分、等像素/延迟预算强对照、其他种子/数据集及官方忽略区评价。

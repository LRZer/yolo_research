# VOC 安全背景模糊 v0：125 轮配对实验最终审计

记录：2026-09-24 约 05:33 CST；05:37 增补逐目标配对诊断。结论先行：**本版未超过原图 YOLOv8n 基线，也没有推理成本优势**。下列结果仅是单种子 VOC 开发集研究结果，不是论文可复现提升或 VOC07 test 盲测结果。

## 实验对象与验收

- 数据：VOC07+12 trainval 中固定 90%/10% 划分；train 14,896 张，dev 1,655 张。VOC2007 test 未用于本次调参或独立评估。
- 两组检测器都由 VOC 上随机初始化训练过 20 轮的相同 YOLOv8n 权重出发，再各训练 125 轮（不是 COCO 预训练；也不是从零只训 125 轮）。模糊组先额外做 5 轮仅门控训练，检测器权重此前逐 tensor 审计与共同起点一致。
- 两组共同参数：seed2027、VOC20类、640 输入、batch64、AdamW 初始学习率0.0005、同一 cosine schedule/增强，物理 GPU0–3、NUMA0、workers4/rank。模糊组在推理时使用图像预测的门控，不读取真实框。
- 独立严格审计 `SAFE_BACKGROUND_LONG_E125_STRICT_AUDIT.json`：两组 CSV 各连续 125 个有限 epoch；`best.pt`/`last.pt` 在 CPU 可加载、类别数20、配置和训练参数一致。Ultralytics 完训会将 checkpoint `epoch` 字段剥离为 −1，因此轮数以连续 CSV 和管理器完训记录共同核实，不把该字段误当第125轮。两组最后权重 SHA256 均已记录。
- 主结果是两组 **第125轮 `last.pt`** 用相同独立 `YOLO.val` 在同一 dev1655 上复评。固定 FP32、imgsz640、batch64、conf0.001、IoU0.7、max_det300、rect=True；两个结果 JSON 记录相同数据 YAML SHA256。`best.pt` 的 dev 最优值只能作为次要信息。

补做了一个**非 AP、非官方 Recall** 的逐目标配对诊断：两组都从相同未处理图像独立预测，再在固定 `conf≥0.25`、同类、IoU≥0.5 下按置信度贪心一对一匹配 3,882 个开发集标注。两组都匹配到 2,576 个；仅基线匹配 147 个，仅方法匹配 139 个，均未匹配 1,020 个。小框（按640缩放后面积<32²）中仅基线4、仅方法3、两组都13/101；中框为48/32、都425/927；大框为95/104、都2138/2854。这个单一阈值下净差仅8个目标，**不足以把 mAP 降低归因于大量漏掉小目标**；AP 还受置信度排序、定位和不同阈值影响。逐类 AP、固定阈值配对和门控保护率之间的因果关系仍未建立。

## 门控与处理强度

CPU 只读审计了 dev1655/3882 个标注框；真实框只用于**事后诊断**，没有参与模型输入。此诊断把各图 LetterBox 到正方形640，而独立 `YOLO.val` 使用 rect batch，故门控百分比是近似诊断，不等同逐张评估时完全相同的几何。

- 目标安全率定义为“框内至少95%像素的模糊许可 `p≤0.1`”。总体 3524/3882 = **90.78%**，小框 93/101 = 92.08%，中框 871/927 = 93.96%，大框 2560/2854 = 89.70%。仍有358个框不满足该保守标准；并非358个已证实漏检。
- 标注保护区平均许可 `p=0.0205`，其中4.87%像素 `p>0.1`。远背景平均 `p=0.3824`，55.95%像素 `p>0.25`、37.41%像素 `p>0.5`；所有有效像素平均 `p=0.1259`、10.44%像素 `p>0.5`。所以模型确实学到目标/背景差异，但并非将大部分图像强模糊。
- 同一方法权重做**事后诊断**：推理混合系数0.5的 AP50–95 为0.495201，设为0（前端仍计算门控但图像不被模糊）为0.494941，差值仅+0.000260。两种都低于原图基线；不能事后把 mix0 选成正式方法。该结果提示：这一权重下的模糊处理本身几乎不贡献 AP，检测器训练轨迹或损失耦合更值得排查，但不能把相关性说成已确认因果。

## 成本及实现偏差

- 训练 CSV 末轮累计用时：模糊组 12,196.8 秒，基线 1,986.75 秒，约 **6.14 倍**。两组均为125轮，但前端在全分辨率处理且参与反传；这不是推理成本比值。
- 独立验证器记录的推理阶段为 2.534 vs 0.695 ms/图，约3.65倍；这不包含全部预处理和后处理。另以固定128张预先解码的 dev 图、同一GPU0和 FP32 测 `YOLO.predict`（预处理+模型+后处理，不含磁盘读取）：batch1 中位数 4.262 vs 2.262 ms/图，batch16 为 **4.400 vs 2.333 ms/图**，均约1.9倍。这是单机短基准，不应泛化到别的 GPU/吞吐条件。
- 推理模型参数约3.970M vs3.010M，额外约0.960M。此前模型摘要 15.4 vs8.1 GFLOPs 不保证完整计入高斯处理，不作为严格端到端 FLOPs 结论。
- 联合损失存在已经审计的**广播偏差**：配置写 `pgb_map_loss_weight=0.25`，但标量辅助损失被加到 YOLO 的三元素检测损失向量后再求和，实际相对系数为 `3×0.25=0.75`。故这不是对预注册 λ=0.25 的严格验证。不得在既有权重上修改系数并称其为同一次训练；若要研究该偏差，需要修复后从同一共同起点重训。

## 判断与下一步

本版本判 **no-go**：不继续在 VOC dev 上扫门控阈值、混合系数或 blur σ 寻找偶然提升。现有证据不能证明“背景模糊没有研究价值”，只能否定本次 v0 实现与训练方式在该协议下的优势。GT-box Oracle 的 AP 提升仍有标注框几何泄露，不能当成可部署方法的上界保证。已知困难还包括 VOC 标注遗漏的 difficult 区域、保护框与真实前景不一致、额外模型容量/反传成本、单种子与有历史故障的服务器内存。

后续优先转向**可靠已发表方法的忠实移植+特定场景适配**。SET 官方实现显示其 HBS 是在检测特征上用训练框构造背景掩码、加学习式残差块和额外训练分支；原始推理路径保留，因此该工作在作者方案中不增加推理分支。它还包含 API 梯度扰动，不能只做 HBS 就称为完整 SET 复现。先以原工作为来源基线，在 VisDrone 等小目标场景做等预算、等分辨率控制，之后仅针对明确失败机制做有限适配；纯移植或堆叠不称为我们的创新。

日期：2026-09-23。状态：代码实现、单测、合成数据和 1% VOC 真实数据冒烟通过；**没有完成正式训练、没有可部署 AP 提升结论**。

## 方法与对旧 PGB 的区别

- 从一张输入图预测单通道“可模糊许可”图 `p`，初始 `p≈0.018`；检测器始终使用模块**自行预测**的图。GT 框仅给训练辅助损失，推理不能读取 GT。
- 固定单尺度高斯滤波与空间残差混合：`I_out=I+mix·p·(Gaussian_sigma(I)-I)`。首版默认 `sigma=8`、`mix=0.5`，这两个值未由正式 dev 对照选定，不代表最优。
- 训练监督：扩张后的真实框是高权重“不模糊”区域；足够远的区域才是低权重“可模糊”候选；两者间过渡带忽略，空标注图不自动当纯背景。当前仅复用批次有效图像区域规则，尚未完整接入原始 VOC difficult 框的几何忽略监督。
- 前端为保留 1/2、1/4 分辨率跳接的多尺度编码—解码 CNN，共 **959,953** 个可学习参数。第一次全卷积版本虽然只有 949,153 参数，却使完整模型估算量达 25.9 GFLOPs；将高分辨率层改为深度可分离算子、容量转移到 1/16 层后，完整模型估算量为 **15.4 GFLOPs**。对应原生 2 类 YOLOv8n 烟雾模型是 8.2 GFLOPs；参数少不代表开销小，实际 640 延迟仍待测。
- 使用已有 YOLOv8n scratch 基线权重分阶段训练；只训图阶段跳过检测器前向，但仍保留训练器所需的损失对象；联合阶段检测损失可传回前端。checkpoint、EMA、验证/推理均经过注册的前端。

## 已执行的验证

1. 新增 8 个针对性单元/集成测试，验证奇数尺寸、高斯混合、初始化近恒等、GT/空框损失、BF16 autocast、前端和检测器梯度、零模糊与原生检测器逐位一致、state_dict 往返；全部通过。
2. 物理 GPU 1、NUMA 0 上两次 12 张合成训练图/6 张验证图、128 输入的单轮完整冒烟通过，包含保存并读取权重。第二版统计为前端 959,953 参数、完整模型 3,965,991 参数与 15.4 GFLOPs；合成图 AP=0 无研究意义。
3. 物理 GPU 1、NUMA 0、BF16、640 输入，使用真实 VOC 严格训练划分的 1%（149 图）进行 1 轮 map-only 冒烟。三次工程联调失败记录保留：普通 BCE 在 autocast 下被 PyTorch 拒绝；map-only 阶段缺少训练器所需 criterion；最终自动验证传入检测预测。逐项修正并补测后，第四次 `voc_map_only_f001_v4_s2027` **完整训练、验证、保存成功**；dev 是 1,655 图，只用于验证工程。
4. 审计第四次 `last.pt`/`best.pt` 均可加载、结果 CSV 恰好一轮；冻结的 YOLO 权重与原始 scratch 基线逐 tensor 完全相同，零模糊推理逐位相同。样例许可图 min/mean/max 为 0.018088/0.018165/0.018204，处理比例 `p>0.1` 为 0；即短烟雾阶段尚未学出有用门控，**不能解释为方法负结果或正结果**。
5. 该次窗口前后 EDAC `mc0 ue_count=0`、`mc1 ue_count=52`，无新匹配内核错误。新近故障 PFN 属 NUMA 1；NUMA 0 历史上也出现过故障，不能宣称健康。用户最新授权优先使用物理 GPU 1–4、实际选择无新故障 NUMA；若跨 NUMA 不合适，宁用 2/3 卡。后续探索拟用 node0 本地 GPU 1–3，不占用他人 GPU7，也不改共享环境。
